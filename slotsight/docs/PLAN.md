# SlotSight Plan

The working plan for SlotSight: where the project stands against its requirements, what's next, and why. Keep it current. Update it whenever work lands, a review happens, or priorities change.

- Requirements (source of truth): [`requirements.md`](requirements.md), IDs R-01 to R-08
- Measured evidence: [`evaluation.md`](evaluation.md)
- Agent and project instructions: [`.claude/CLAUDE.md`](../../.claude/CLAUDE.md)

Paths in this document are relative to the `slotsight/` folder unless they start with `slotsight/` or `.claude/`.

## How to use this document

- **Requirement status** shows the current verdict for each requirement. Update a row only when evidence changes (an evaluation run, a timing test, a demo).
- **Roadmap** lists the work, grouped into milestones. Tick the checkboxes as items land, and add new items under the right milestone, including the requirement IDs they affect.
- **Review log** records dated findings from code reviews. Add a new dated entry for each review instead of editing old ones.
- **Decisions log** records choices that change direction or scope, with the reasons.

## Roadmap

### Milestone 1: Meet the requirements (current focus)

#### 1A. Correctness fixes (blocking for every requirement)

- [x] **Separate demo mode from real inference.** When a real frame is supplied, an empty detection list means every slot is vacant. The demo pattern runs only when `frame is None` and no model is loaded. A detector exception is reported (logged, plus an error status in the response), never replaced by demo data. With a model loaded and no frame yet, slots show as unknown. A frame uploaded with no model returns HTTP 503. *(R-01, R-02)*
- [x] **Make `GET /api/status` read-only.** Only processing a frame should append history. Demo snapshots are never recorded. Threshold changes, config saves and file-less `POST /api/process` calls don't record either. *(R-08)*
- [x] **Replace the corner-in-polygon check** with an overlap ratio, compared with a configurable `overlap_threshold` in `settings.txt` (default 0.4). The ratio is the larger of: intersection / slot area, and intersection / box area. The second term keeps small vehicles in large slots from being missed. It is computed with `cv2.intersectConvexConvex` against the slot's convex hull. README updated. *(R-01)*
- [x] **Give vacant slots a real confidence score.** Vacant confidence = 1 − max(detection confidence × (overlap / overlap_threshold)²) over detections that overlap but fall below the threshold. Occupied confidence is the strongest matching detection's score. The detector now runs with a 0.1 confidence floor, so weak detections push slots to "unknown" instead of "vacant". *(R-07)*
- [x] **Make defaults consistent** across `app.py`, `settings.txt` and the slider default (review 0.7, overlap 0.4, `yolo11s.pt`). Resolve `model_path` against `BASE_DIR`. Reload the model when the path changes. `SLOTSIGHT_MODEL` now overrides `settings.txt`, as the README describes.
- [x] **Keep the upload snapshot after a config save.** Re-classify `latest_frame` with the new slots instead of falling back to demo data. Cached detections are reused, so no new inference runs.

#### 1B. Inputs and live updates (R-03, R-04)

- [x] **Process the whole video.** Frames are sampled every `sample_interval_s` seconds of video time (default 2 s) in a background job (`sources.py`). Each sampled frame logs one row per slot with its video offset (`frame_time_s`). With an optional "recorded at" start time, `timestamp` = start + offset.
- [x] **Add a live source.** `SourceWorker` reads an RTSP/HTTP URL, webcam index or local video path, drains frames continuously, processes one every `sample_interval_s` seconds, and reconnects up to 5 times after dropouts. The API is `POST /api/source`, `POST /api/source/stop` and `GET /api/source`, with matching UI controls. Stream credentials are removed from displayed and logged names. Inference runs outside the state lock, so status polls stay fast (≤20 ms measured during processing).
- [x] **Let the upload field accept video** (`accept="image/*,video/*"`). Job progress, frame count and per-frame processing time show under the source panel.
- [x] **Add a timing test.** `slotsight/scripts/measure_update_interval.py` runs a source at recorded speed through the full pipeline and reports the results to `docs/evaluation.md`. First run on this laptop (CPU only, synthetic 1080p footage): 0.09 s per frame, 4.05 s worst-case on-screen gap. The model now runs a warm-up inference when it loads, which removed a 1.7 s first-frame delay. *(R-04 evidence)*
- [ ] **Re-run the timing test with real lot footage** (and a real camera stream, if available) to confirm R-04 under real conditions. *(R-04)*

#### 1C. Dashboard and evidence (R-01, R-02, R-05, R-06, R-07, R-08)

- [x] **Colour map polygons by status.** `renderMap` draws each slot as an SVG polygon with a `status-<status>` class (green/red, plus yellow with a dashed edge for unknown). It adds a pinned chip with the slot ID and a status symbol (○ ● ?), so status doesn't rely on colour alone. The map corner shows "Updated hh:mm:ss", plus the capture time or video offset when known. The hover/focus tooltip and the activity list show each slot's status, confidence and update time. The backend adds a per-slot `updated_at`, which stays at the frame's processing time when a config or threshold change re-classifies it. The tooltip now follows each 2 s refresh instead of showing the old reading. The activity list is built with DOM calls instead of `innerHTML`. *(R-06)*
- [x] **Build an evaluation harness** (`eval/evaluate.py`). Inputs: `eval/labels.csv` (`frame, slot_id, true_status, condition, occluded`), frames in `data/eval_frames/`, and `slots.json`. It runs the dashboard's own detection, overlap and review-threshold code. Outputs, with PASS/FAIL/NO DATA verdicts:
  - per-slot accuracy (unknown counts as wrong) with coverage, a confusion table and a per-slot table
  - free-count match rate on fully labeled frames, plus mean error and over-reported frames
  - accuracy per condition (daytime, evening, rain) and the evening/rain ratio to daytime
  - occluded cases split into correct, unknown and wrong (including false "free"), plus how many wrong guesses the review threshold held back as unknown

  Detections are cached (`data/eval_cache.json`), so threshold comparisons don't repeat inference. `--write` adds the report to the accuracy section of `docs/evaluation.md`. The scoring logic, label validation and an end-to-end YOLO run were checked on hand-built and synthetic cases. *(R-01, R-02, R-05, R-07 evidence)*
- [ ] **Collect and label a reference test set** from the target lot, covering daytime, evening and rain, and including partly hidden cases. Store the labels (not raw video) in the repo. *Waiting on footage (2026-11-17). The tools are ready: `docs/recording-guide.md` (what and how much to record, camera setup, labeling rules), `eval/extract_frames.py` and the `/label` page.*
- [ ] **Tune `review_threshold` and `overlap_threshold`** on a held-out split and record the chosen values and their results. `evaluate.py --only "tune/*" --overlap-threshold/--review-threshold` re-scores the tune sessions from cached detections; verdicts use `--exclude "tune/*"`. *Blocked on the reference set.*
- [ ] **Re-check R-06 in the demo with lot footage** once the reference footage exists. *(R-06)*
- [x] **Proxy evaluation on public data** (a one-off run with a local script that isn't committed; PKLot subset of 603 frames and 32,831 slot labels): 52.7 % per-slot with the default model and thresholds. Recorded in `docs/evaluation.md` as proxy evidence, not as meeting any requirement. *(R-01, R-02, R-05 proxy)*
- [x] **Detection resolution setting** (`inference_size`: 640 / 960 / 1280 in the Configure dialog, Ultralytics models only; default 640). The evaluation cache keys on it, and `evaluate.py --inference-size` overrides it per run. *(R-01, R-07)*
- [x] **"Doesn't look empty" safeguard** (`appearance.py`, setting `empty_check_threshold`, default 0.8). Videos and live sources only: a vacant reading whose slot differs too much from its learned empty appearance becomes unknown. On PKLot, occupied shown as free fell 61 % at a cost of 4.0 % of truly empty slots. The evaluation scores sessions in time order with the check and reports what it caught and cost. *(R-07)*
- [x] **Per-slot classifier** (`classifier.py`, base weights trained on PKLot, `eval/train_classifier.py` to fine-tune on the lot's tune sessions). It is the primary decision, with the detector as a safety vote for "vacant". PKLot proxy, unseen views: 97.8 % per-slot (from 52.7 %), occupied shown as free 29 (from 9,167), or 13 with the empty check; R-04 still passes (4.16 s worst case on synthetic footage). *(R-01, R-07)*
- [ ] **Fine-tune the classifier on the lot's pilot / tune sessions** (`python slotsight/eval/train_classifier.py`) and evaluate on the test sessions; check evening and rain, which PKLot doesn't cover. *(R-01, R-05)*
- [x] **Low-light robustness** (synthetic dusk and night on PKLot): the classifier was confidently wrong at night (16,501 occupied shown as free). Low-light training augmentation fixed dusk (94.4 %) and made night fail safe (238), with no daylight loss; the base weights were retrained. *(R-05, R-07)*
- [ ] **R-02 at risk:** exact free-count match needs per-slot errors well under 1 % on a 10-30-slot lot. Measure it on the lot's test sessions, including with smoothing (score sequences, see Milestone 2), and weigh the empty check's cost to R-02 against its R-07 benefit. *(R-02, R-07)*
- [ ] **Revisit the empty-check default** with the lot's data: with the classifier it caught 27 missed cars on PKLot but turned 158 empty slots unknown. *(R-07)*
- [x] **Risk: detector recall on dense, distant or angled views** (found on PKLot). Addressed by the per-slot classifier (see above); the detector now only votes. Missed cars read as confidently free, which hurts R-01 and R-07. Measure the target lot first; if it shows the same problem, the options are a configurable inference size (1280 px helped the closer PKLot views by 10-20 points), RF-DETR (far fewer false "free"), or a per-slot classifier (the method behind published 95 %+ PKLot results, which needs training data). *(R-01, R-07)*
- [x] **Fix the R-08 data issue.** The old file was archived as `occupancy_history-2026-11-17.csv` (gitignored) and a clean file in the new format starts on the next run. *(R-08)*

### 2026-11-18: Code review of the dashboard UI work (`cf93312..4c5eeba`)

Covers the live-state, change-feedback and layout-editor pass (`8b89f26`), Settings with `POST /api/settings`, the classifier switch-off fix, type, top bar and themes (`4ca7d9b`), and the wayfinding redesign (`4c5eeba`). All ten were confirmed by reading the code; findings 3, 6, 8 and 9 were then reproduced by regression tests, and the browser-side ones were checked in a browser after the fix.

1. **A dead source's last count looks current (high, R-06, R-07).** Staleness is only checked while the job is `running`. When a live source ends in `error` (after its reconnects fail) or `stopped`, the state falls back to "Last reading", the map is no longer dimmed and the LED lights the frozen free count again.
2. **The LED stays lit while polling is paused (medium, R-06).** With Auto refresh off, or during Edit layout, nothing is refreshed but the free count still glows as current.
3. **A settings change hides the camera warning (medium).** The `/api/settings` response has no `camera` (or `job`), so rendering it clears the "camera may have moved" alert and footnote until the next poll, or indefinitely with Auto refresh off.
4. **The Settings JSON mixes ids and points while editing (medium).** It takes ids from the saved layout and points from the unsaved edit by index; Apply then saves the mixed layout and replaces `state.slotConfig` under the open editor, so later drags change the wrong bays.
5. **Ctrl+Z or Undo during a corner drag (medium).** The drag stays active over the restored layout: the next move throws a TypeError if its bay no longer exists, or moves another bay's corner.
6. **`/api/config` can revert a setting saved at the same time (low-medium).** It re-saves all four dialog settings from a copy read before its classifier pre-compute, though the layout editor now sends only the slots.
7. **Overlapping settings saves aren't ordered (low-medium).** Two quick threshold saves can finish in either order on the server and in the page; `seq` only hides the "Saved" text.
8. **`/api/settings` switching the classifier on doesn't check the layout (low).** Output computed for the old layout can be applied to a layout saved in between, then cached.
9. **A frame computed just before the classifier is switched off is still decided by it (low).** `snapshot()` uses passed-in classifier output without checking the setting; the guard is only in `reclassify_latest_frame`. One logged reading at most.
10. **If `theme.js` fails, the dashboard never loads (low).** `app.js` calls `window.slotsightTheme` unguarded at the top level; an old browser without `MediaQueryList.addEventListener` (Safari before 14) or a blocked file stops polling, the map and trends.

**Resolution (2026-11-19):** all ten fixed. `tests/test_review_fixes_3.py` adds 4 regression tests that make the server-side races deterministic (the "meanwhile" change is made inside the classifier call that runs outside `state_lock`); all 4 fail on the pre-fix `app.py` and pass after. The suite is 259 tests. Fixes: a live camera or stream that stopped or failed shows "Camera disconnected" / "Camera lost" and its last reading is stale (map dimmed, LED unlit), only while the reading on screen came from it; a finished video keeps its last reading undimmed (1); the LED is lit only while polling is on and no edit is open (2); `/api/settings`, `/api/review-threshold` and image uploads answer with the full status payload, and the page renders the camera check only from a payload that has it (3; uploads had the same gap); the Settings JSON shows the saved layout, and Apply is disabled with a note while Edit layout has unsaved changes (4); Undo or Ctrl+Z during a drag or a drawing cancels only that gesture (5); `/api/config` saves only the settings it was sent, under the lock (6); settings saves are queued so the server and the page apply them in order, and a failed save reverts to the value saved at that point (7); `/api/settings` drops classifier output when the frame or the layout changed meanwhile (8); `snapshot()` ignores classifier output whenever the classifier is switched off, replacing the special case in `reclassify_latest_frame` (9); `theme.js` falls back to `addListener`, and `app.js` hides the Appearance control instead of stopping when `theme.js` is missing (10).
